# AnoEdge / AnoGraph：在固定内存里筛查不断到达的边

论文将边的两个端点分别哈希到矩阵的行与列。近期大量来自一组端点、流向另一组端点的边，在压缩矩阵中可能形成稠密块。算法在摘要上寻找这些块，避免把每条历史边都放在内存里。[KDD 出版记录](https://doi.org/10.1145/3580305.3599504) · [作者全文](https://arxiv.org/pdf/2106.04486)

**同一篇论文有两种告警。** AnoEdge-G 与 AnoEdge-L 给新到达的一条边打分；AnoGraph 与 AnoGraph-K 评价一个时段的图。哈希压缩可支持高速更新，但候选块内可能混入由碰撞产生的无关实体。“某时段变得异常”也不能自动指认具体账户。[作者全文，算法部分、表4–5](https://arxiv.org/pdf/2106.04486)

**证据的边界。** 表3列出 DARPA、ISCX-IDS2012、CIC-IDS2018 与 CIC-DDoS2019，均为网络流量数据。表4比较边级 AUC 和运行时间，表5比较图级。运行时间统计明确剔除了输入输出成本。其证据支持在通信流上用紧凑摘要筛查异常，但测到的耗时不能直接换算成生产平台端到端延迟。[表3–5及实验说明](https://arxiv.org/pdf/2106.04486)

**复现问题。** 按事件回放合成交易图，逐步增加同时活跃的账户数和热门收款方。固定可用内存，分别测边级 AP、窗口误报和端到端延迟，并记录多少告警无法从摘要反查到唯一候选群体。
