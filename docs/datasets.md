# FinGraph 金融图异常数据集索引

核查日期为 2026-11-20。下列 7 个数据集或数据系列覆盖四种预测对象。先选定一条预测记录对应的业务对象，再选数据与指标。每项均提供原论文和发布方的数据入口。本索引只收录描述和链接；“待核”表示已有来源不足以确定该项。

| 学生希望回答的问题 | 预测记录 | 合适的首个数据集 | 扩展比较 |
| --- | --- | --- | --- |
| 有限风险标签能否识别高风险用户？ | 一个借贷用户或链上地址 | DGraph-Fin | DIAM 的地址标签，有监督与半监督采用同一测试集 |
| 能否及时筛出可疑交易？ | 一笔交易 | Elliptic 的交易**节点** | AMLworld 和 TransXion 的交易**边**，需要不同的模型输出层 |
| 一组资金路径是否值得合并调查？ | 一个候选子图 | Elliptic2 | 分别评估已给定候选的分类和自主发现候选的能力 |
| 每天应优先复核哪些既有告警？ | 一条已生成的告警 | SynthAML | 以固定复核预算报告 Precision@K、Recall@K |

## 数据卡

### 1. Elliptic Bitcoin｜比特币交易节点

- **图与标签。** 203,769 个节点各代表一笔交易，234,355 条有向边连接产生和花费同一输出的交易。Elliptic 根据交易发起实体的归属给出合法、非法或未知标签。未知交易可构成上下文；计算二分类指标时只使用已标注交易。
- **原始评测与用途。** 49 个时间步中，原论文用前 34 步训练、后 15 步测试。适合建立监督模型与低标签预算模型的时间基线。166 个节点特征中有邻居聚合特征；模拟交易发生当时打分时，要核对聚合所用的后继交易在当时是否已出现。
- **获取与许可。** 发布方在 Kaggle 提供特征、边表和标签。此次可核对到数据页，具体许可条款待核。[原论文（KDD 2019 金融异常检测研讨会）](https://arxiv.org/abs/1908.02591) · [Elliptic 数据页](https://www.kaggle.com/datasets/ellipticco/elliptic-data-set)

### 2. Elliptic2｜比特币地址簇上的候选子图

- **图与标签。** 背景图约有 4,930 万个地址簇、1.96 亿条资金往来边。研究者依据资金路径的起讫实体及其归属构造候选子图，标出 119,047 个 licit 与 2,763 个 suspicious。标签附着于整个候选。“可疑”表示作者定义的路径证据，单个地址的风险仍需单独验证。
- **原始评测与用途。** 论文按候选子图随机划分训练、验证、测试，比例为 80/10/10。适合研究背景图、路径边界对候选排序的贡献。若目标是在全图发现案件，另需生成候选，报告候选召回率以及每发现一个命中所需复核的候选数。
- **获取与许可。** 发布方 Kaggle 数据页可定位；作者 GitHub 提供预处理与 CSV 字段说明，其 README 中旧数据链接本次转至企业首页。数据文件许可待核。[原论文（KDD 2024 金融机器学习研讨会）](https://arxiv.org/abs/2404.19109) · [Elliptic 数据页](https://www.kaggle.com/datasets/ellipticco/elliptic2-data-set) · [作者使用指南](https://github.com/MITIBMxGraph/Elliptic2)

### 3. DGraph-Fin｜借贷紧急联系人网络

- **图与标签。** 3,700,550 个节点代表金融平台用户，4,300,999 条有向边记录某位用户将另一人列为紧急联系人的行为。原研究用长期逾期且多次催收无回应等业务条件界定欺诈正例。代码中的 0/1 为前景正常/欺诈，2/3 为背景，可进入消息传递；监督损失与二分类评测只覆盖前景。
- **原始评测与用途。** 官方按节点随机划分 70/15/15，边附联系人申报时间。复现随机节点任务时保留原划分；研究前瞻预警时另设观测截止时点，报告边、属性和标签的可见性。适合研究少量风险标签下，背景关系对借贷风险分类的作用。
- **获取与许可。** 本卡使用 DGraph-Fin 第一版。按官方入口选择对应版本；论文附录说明申请者需提供姓名和邮箱、同意使用协议。当前条款以发布方协议为准，数据的产业使用授权待核。[原论文（NeurIPS 2022 Datasets and Benchmarks）](https://proceedings.nips.cc/paper_files/paper/2022/hash/8f1918f71972789db39ec0d85bb31110-Abstract-Datasets_and_Benchmarks.html) · [官方数据页](https://dgraph.xinye.com/dataset) · [使用协议](https://dgraph.xinye.com/clause)

### 4. AMLworld / IBM Transactions for AML｜合成银行交易边

- **图与标签。** 节点为账户，边是带时间的转账或支付，同一对账户可多次交易。模拟器为每笔交易给出是否涉洗钱的标签。HI、LI 表示模拟环境中较高或较低的洗钱发生率，各有不同规模；适合研究同一方法随基础发生率变化的表现。
- **原始评测与用途。** 原论文按时间排序，约以 60/20/20 划分交易。GNN 验证图含训练和验证期交易，测试图含三个阶段交易，指标只在相应窗口内计算。需要宣称“逐笔实时”时，应另设每笔交易仅访问过去边的协议，记录它与原协议产生的差异。
- **获取与许可。** IBM 提供 Kaggle 数据入口并明确数据采用 CDLA-Sharing-1.0，GitHub 仓库采用 Apache-2.0。固定 HI/LI、大小、版本后再比较模型。[原论文（NeurIPS 2023 Datasets and Benchmarks）](https://research.ibm.com/publications/realistic-synthetic-financial-transactions-for-anti-money-laundering-models) · [发布方说明与许可](https://github.com/IBM/AML-Data) · [数据下载](https://www.kaggle.com/datasets/ealtman2019/ibm-transactions-for-anti-money-laundering-aml)

### 5. SynthAML｜合成银行告警及关联交易流水

- **记录与标签。** 作者以丹麦 Spar Nord 银行资料拟合生成模型，公开 20,000 条合成告警及超过 1,600 万条关联交易。两表通过告警 ID 相连，交易包含金额、时间、出入账方向和类型。目标是告警最终被上报或驳回。公开字段缺少交易双方账户 ID，无法据此重建完整的客户间转账网络，也无法为每笔交易赋予洗钱真值。
- **原始评测与用途。** 论文以 2020 年告警训练、2021 年告警测试，合成告警日期的精度只支持按季度边界切分。适合做告警优先级、队列预算和跨季度漂移评估。复现公开数据部分时，报告“合成训练、合成测试”；原文另外使用的银行内部测试数据须独立授权。
- **获取与许可。** 原论文指定 Figshare 版本化存档，下载时分别记录两张表的文件版本。数据条款待核。[原论文（Scientific Data，2023）](https://doi.org/10.1038/s41597-023-02569-2) · [作者数据集（Figshare v1）](https://doi.org/10.6084/m9.figshare.c.6504421.v1)

### 6. TransXion｜带账户画像的合成交易时序多重图

- **图与标签。** 47,526 个账户在 365 天发生 3,029,170 笔模拟交易，其中 4,641 笔带洗钱标签，约占 0.15%。账户画像和带时间交易边分别发布，重复往来保留。可与 AMLworld 对照，研究同一模型是否依赖特定模拟器产生的异常形态。
- **原始评测与用途。** 论文 §5.3.1 采用交易边级有监督分类，按 60/20/20 划分，仅用边属性作跨数据比较。该段未说明分界是否严格按时间，复现时记录实际索引生成方式。使用画像的扩展实验单列，并在相同告警预算下与边属性基线对照。
- **获取与许可。** 作者 GitHub 的 `data` 目录含交易、个人和商户表，交易 CSV 使用 Git LFS。README 指向两个代码子模块的许可；数据 CSV 的单独授权范围待核。[原论文（KDD 2026 Datasets and Benchmarks）](https://doi.org/10.1145/3770855.3817550) · [作者全文](https://arxiv.org/html/2604.17420v1) · [作者数据及代码](https://github.com/chaos-max/TransXion)

### 7. DIAM 加密货币多重图｜以太坊与比特币地址分类

- **图与标签。** 作者发布 Ethereum-S、Ethereum-P、Bitcoin-M、Bitcoin-L 四张有向交易多重图，节点为地址，边为可重复的链上转账。以太坊正例是已标注的钓鱼地址；比特币正例为赌博或混币服务关联地址。后者反映服务归属，不能据此判定任一笔交易构成洗钱。数据卡区分已标异常、已标正常和未标注节点。
- **原始评测与用途。** 原论文将有标签节点按 2/1/1 分成训练、验证、测试集，训练五次并汇总。适合检验重复边、方向及交易金额对地址筛查的贡献；另做低标签实验时只遮蔽训练标签，保持验证与测试对象一致。作者数据卡说明划分可由基准代码构建。
- **获取与许可。** 作者 Hugging Face 仓库发布四个图；使用时记录图名、revision、地址标签定义和当次划分。数据卡许可字段为 `other`，具体适用条款待核。[原论文（CIKM 2024）](https://doi.org/10.1145/3627673.3679707) · [作者数据卡与下载](https://huggingface.co/datasets/Tommy-DING/crypto-illicit-account-detection-multigraphs) · [作者实现](https://github.com/TommyDzh/DIAM)
