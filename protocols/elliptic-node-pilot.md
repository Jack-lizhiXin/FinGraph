## 先把样本单位说清楚

Elliptic 中一个节点是一笔比特币交易，一条有向边表示资金从一笔交易流入另一笔。发布者按发起交易的实体类别提供标签。全图有 203,769 笔交易、234,355 条边，其中 4,545 笔标为 illicit（类别 1），42,019 笔标为 licit（类别 2），其余 157,205 笔为 unknown。这个任务预测发布者的交易标签。迁移至银行账户监测时，要重新定义账户级真值和评价单位。[原文第 2 节](https://arxiv.org/pdf/1908.02591) · [作者发布的数据](https://www.kaggle.com/datasets/ellipticco/elliptic-data-set)

数据含 49 个时间步，相邻时间步大致相隔两周。每一步对应不足三小时的交易快照，公开图的边均落在同一步内。Weber 等在 KDD 2019 金融异常检测 Workshop 使用前 34 步训练、后 15 步测试，并比较 94 个局部特征及 166 个完整特征等设置。若需复现原文，请按第 4 节的模型、特征、时间切分及指标另存结果。[论文信息](https://arxiv.org/abs/1908.02591) · [原文第 2、4 节](https://arxiv.org/pdf/1908.02591)

| 40–49 | 一次冻结测试 | 对该段所有节点产生分数。两条路线共用同一份测试 ID、已标掩码、时间步、候选池和 K，不根据测试标签重选设置。 |

程序先导出各窗口的节点和标签计数、掩码版本及校验值。测试标签单独交给评价程序，训练脚本仅获得该路线允许看到的标签。用于打分的公共结构上下文可包含无标签邻居。若训练目标主动利用未标注样本，必须登记其范围和作用，单列“正常标签＋未标注训练池”实验。公开标签缺少逐笔确认日期，因此试验假定训练段已知标签在拟合时可得，无法据此验证真实业务中的标签延迟。

## 在评分时刻能看到哪些特征

**主比较只用可解释的上游结构。** 首轮在发布的采样图内重算两个特征。第一项是当前交易的直接前序交易数取 `log1p`。第二项是对这些前序交易各自的直接前序交易数取 `log1p` 后求平均。没有可见前序时两项按 0 填，并记录缺失前序的节点比例。每个目标仅沿入边访问至多两跳上游交易。原始 ID 和时间步只用于对齐、切分与排序。图规模、度数和归一化系数均按允许的入边计算。同窗节点的先后关系只能借助有向资金依赖，匿名 ID 不提供时间顺序。[原文的数据构造](https://arxiv.org/pdf/1908.02591)

首轮禁用指向后续交易的出边、全窗双向传播、在全图上预计算的社区或节点嵌入。数据末尾 72 项聚合特征使用前向及后向的一跳邻居。前 94 项虽称为局部特征，也含地址收支统计，匿名字段难以逐项证明其形成时点。需要比较时，分别建“发布版局部特征”和“发布版完整特征”的快照实验，明确标记输入来源。一个模型若依赖完整快照，要在对应快照协议内与同输入基线比较。[原文第 2.1、2.2、4 节](https://arxiv.org/pdf/1908.02591)

以上安排检验新时间步上的外推，以及限制模型只读取上游结构后的表现。公开数据缺少完整的逐笔可用时点，且只保留抽样形成的子图。若要验证逐笔在线预警，还需具有原始事件、特征和标签可用时点的数据，按到达顺序回放。

## 怎么评价前 K 笔告警

- **已标交易上的排序。** 合并测试时间步中标签为 licit 或 illicit 的节点，以 illicit 为正类计算 AP，即各分数阈值下精确率按召回率增量加权之和。每步另列正负样本数和 AP，以观察不同时间段的差异。某步没有已知正例时标“无可评正例”。如使用梯形积分计算 PR-AUC，应单列指标和实现。
- **已标候选池内的 P@K。** 首轮预设每步 K=20，属于试验参数。仅将本步已标的交易按分数从高到低排序，取前 k 笔，其中 k=min(20, 已标候选数)。报告其中已知非法笔数除以 k。相同分数按统一、固定的交易 ID 排序。空池记“无可评样本”。
- **全量告警名单。** 另将该步所有交易排序并取前 k 笔，其中 k=min(20, 全部候选数)。若其中 p 笔已标非法、l 笔已标合法、u 笔未知，则可核实的命中比例下界为 p/k，上界为 (p+u)/k。同步给出标签覆盖率 (p+l)/k。榜内已标样本的命中率 p/(p+l) 单列，分母为 0 时记“不可估”。区间只利用现有标签确定，不能当作置信区间。
- **汇总口径。** 逐时间步保留分子、分母、实际告警数和标签覆盖率。跨步汇总告警指标时先加总笔数再计算比例。目标为零或无样本的窗口保留在结果表，便于同行检查评价范围。
