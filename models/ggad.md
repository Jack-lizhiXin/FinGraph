# GGAD · 只有正常标签时，生成伪异常能否改善排序？

**当前状态**　候选（文献已收录）  
**建卡日期**　2026-11-20。运行人、复核人由首次周会认领。

Hezhe Qiao 等在 NeurIPS 2024 提出 GGAD。训练阶段只给出一部分已知正常节点。模型结合这些节点和周围图结构生成伪异常表示，用它们训练判别器，再为待评价节点打分。输入为节点属性、邻接关系及正常种子节点编号。伪异常用于训练，检测效果须以独立标注评价。[论文](https://proceedings.neurips.cc/paper_files/paper/2024/hash/085b4b5d1f81ad9e057ad2b3de922ad4-Abstract-Conference.html) · [作者代码](https://github.com/mala-lab/GGAD)

## 第一次复现拟做什么

1. 先跑作者的小规模 Photo 基准。记录代码提交号、数据文件校验值、Python、PyTorch、DGL 版本和内存。作者 README 记录 Python 3.7、PyTorch 1.6.0。按 README 获取预处理数据，保存为作者仓库下的 `dataset/photo.mat`。在该仓库根目录拟执行下方命令。
2. 从 `utils.py` 核对训练索引、正常种子数，以及占训练正常数和全图节点数的比例。程序中的 `abnormal_label_idx` 从正常种子中抽取，对应用于生成伪异常的样本。记录测试集中真实异常节点数和指标计算函数。[作者数据处理实现](https://github.com/mala-lab/GGAD/blob/main/utils.py)
3. 在运行前约定采用最后一次固定评估时点。作者脚本会周期性打印测试指标，挑选测试集表现最高的一轮会高估效果。保留原始日志、固定时点的 AUROC 与 AP 及对应节点分数，核对原论文表 1 的指标定义与正常标签预算。[作者训练入口](https://github.com/mala-lab/GGAD/blob/main/run.py)

```bash
python run.py --dataset photo --seed 0
```

**金融场景对照**　再按 [Elliptic 节点试验方案](../protocols/elliptic-node-pilot.md) 中的仅正常标签设置，先建立以中位数和中位绝对偏差为参照的距离基线。接入 GGAD 时检查生成伪异常用到的邻居、方向和跳数。若需要完整双向邻接，转入独立的快照协议。如将未标注节点直接用于训练损失，另列训练池条件。若引入 [CR-Aug](../notes/cr-aug.md)，两者须使用相同的正常种子、时间边界和可见图。比较哪类交易的排名发生改变，并检查少数正常群体是否更容易出现误报。

**验收证据与局限**　首次运行和独立复核均待执行。仅在复核者可定位版本、命令、切分和固定评估时点后填写实测结果。作者小图入口会构造稠密邻接和相似度矩阵，迁移到更大的交易图时先记录规模与内存需求。正常种子的来源决定了模型学到哪些正常模式，金融应用中需说明这些标签如何确认，未被调查的交易应保留未知状态。
