# Elliptic++ 的一次支付可以属于两种检测任务吗？

Elmougy 与 Liu 在 KDD 2023 对同一比特币链上样本构建交易与地址视图。交易→交易的边表示前序资金如何流入后序交易；地址–交易图可连接资金出入的地址与交易。一笔交易有多个相关地址，某个地址也会参与多笔交易。把地址标识、交易标识和标签表分开，是复用特征的前提。[论文](https://doi.org/10.1145/3580305.3599803) · [作者数据表](https://github.com/git-disl/EllipticPlusPlus)

**两种分母。** 交易表中 203,769 笔交易有 4,545 笔非法、42,019 笔合法、157,205 笔未知。地址表有 822,942 个地址。只评价已标注交易时，应同时报告覆盖率，避免让读者以为测试覆盖整条链。地址识别能力另用地址级标签衡量；同一交易额按关联地址数展开，会重复计算业务金额。[作者 Dataset Summary](https://github.com/git-disl/EllipticPlusPlus)

**协议的争议在哪里。** 原文 §4.1 描述以 1–34 步训练、35–49 步测试，§4.3 区分非法类 F1 与 Micro-F1。2026 年一项后续复核认为，发布实现的地址分类切分按行位置，且部分地址特征聚合了未来活动。这是对地址级实验的具体质疑，应将原文表述、实现审计和交易级结果分别引述。[原文 §4](https://arxiv.org/abs/2306.06108) · [后续复核 §2、表 4，预印本](https://arxiv.org/abs/2611.04000)

**组内实验。** 冻结一份交易 ID 清单作为评估对象。先评交易特征，再增加仅由评分时可见邻域算出的地址统计。逐时间段记录已标注交易数、非法数、AP 及复核预算下的命中数。若转而给地址预警，则另设首次出现地址与历史出现地址两组，重新定义评分截止时间。
